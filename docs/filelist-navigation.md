# 本地文件清单导航方案

状态：功能已实现，生成器回归及真实 LazyVim/Snacks、clangd、pyright、verible 集成测试通过。2026-09-08，用户明确接受 Q1–Q3 的建议，并授权后续未明确回复的选项采用建议值；下述其余决定按这一授权确定。

## 已确认的目标

- 项目根生成本机专用的 `tree_t.f`，记录指定目录中指定后缀文件相对于该项目根的路径，不纳入 Git。
- 支持 C/C++ 与 Python，默认后缀为 `.c/.h/.cc/.cpp/.cxx/.hh/.hpp/.py/.pyi`；命令允许自定义后缀。增加其他后缀不会自动增加对应语言的符号解析能力。
- 允许显式指定项目外的 SDK，清单可以包含 `../sdk/include/dp.h`。
- include 按清单定位；函数、结构体等符号优先用 LSP，失败后列出清单内的文本候选。语义引用与文本匹配分别标明。
- 复用现有 Neovim、Snacks 和 rg，不增加 Neovim 插件，不要求修改项目构建脚本。

## 生成命令与清单格式

包内命令为 `nvim-filelist`。默认从当前目录生成，也可以通过 `--root` 明确指定项目根；必须显式提供至少一个扫描目录，不默认扫描整个项目或整个 SDK。

```bash
# 安装后的普通终端；目录名称仅作示例
~/.local/opt/lazyvim-offline/tools/bin/nvim-filelist \
  --root "$PWD" --ext c,h,cc,cpp,cxx,hh,hpp,py,pyi \
  -- src include ../sdk/include
```

使用自定义安装前缀时使用该前缀下的 `tools/bin/nvim-filelist`。Neovim 包装器已经把该目录加入其子进程的 PATH；普通终端不默认继承它，文档应提供可直接运行的完整命令。

结果示例（按路径排序）：

```text
../sdk/include/dp.h
include/app.h
src/app.c
```

- 基于 GNU find、realpath 和 sort 生成；扫描目录参数相对于 `--root` 解释，也允许绝对目录参数。输出始终是相对于清单项目根的文件路径。
- 一行一个文件，不添加引号，不作 shell 展开，不包含编译参数、`+incdir+` 或嵌套 filelist 指令。读取器忽略空行并兼容 CRLF。
- 递归扫描显式目录，按后缀区分大小写，排序去重。支持空格、中文和普通特殊字符；含换行或回车的文件名不能用此格式无歧义表示，生成时报告错误。
- 默认只排除 Git 元数据目录；不自动排除 build 或被 `.gitignore` 忽略的文件，以免漏掉 SDK 和生成头文件。用户通过缩小扫描目录控制范围。
- 默认跟随作为扫描参数传入的目录符号链接，不递归跟随扫描过程中遇到的目录符号链接；需要这类 SDK 时显式把其目录链接作为扫描参数。保留可访问的文件符号链接路径，不按真实目标强行合并不同路径。
- 任一目录不存在、扫描失败或没有匹配文件时报告错误并保留原清单；成功时以临时文件加重命名方式整体替换。更新是重建快照，手工增删的条目会被下一次生成覆盖。

## Git 与刷新

- 在所属仓库的本地排除文件中添加只匹配该清单的规则，通过 `git rev-parse --git-path info/exclude` 定位，支持 `.git` 是文件的 worktree。项目内的嵌套根使用相应的仓库相对路径规则。
- 生成前检查目标是否已经被 Git 跟踪；若已跟踪，停止并说明排除规则无法取消跟踪，不自动修改索引或远端。普通排除规则不能阻止用户主动 `git add -f`。
- 非 Git 项目直接生成；不修改项目 `.gitignore`，不增加全局 Git 规则，不提交清单。
- 新增、删除文件或 SDK 路径变化后重新执行生成命令；仅修改已有文件内容不需要重建路径清单。
- 首版在每次导航或清单搜索开始时重新读取清单，不建立目录监视器、不自动运行构建、不需要重启 Neovim。过期或不存在的条目跳过并汇总提示；空清单不允许退化成全盘或全项目搜索。

## 快捷键行为

| 入口 | 已有清单时的行为（默认 LSP 优先模式） |
| --- | --- |
| `gd` 位于字面量 include 行 | 在清单中定位头文件；唯一候选直接打开，多候选由 Snacks 展示完整路径与预览 |
| `gd` 位于函数、结构体等符号 | 优先请求 LSP 定义；无支持客户端、返回空、错误或超时后，优先展示清单内的符号定义候选，未识别到定义则提示并回退全部同名文本 |
| `gr` | 优先使用 LSP 引用；无结果或不可用时展示清单内同名文本，排除已识别的定义位置，标题明确为非语义引用 |
| `Ctrl-o` | 通过 Neovim 跳转列表回到来源位置 |
| `:FilelistGrep` | 跳过 LSP，在清单范围查找光标下完整标识符；支持显式传入一个搜索词 |
| `:FilelistUse /path/to/tree_t.f` | 在当前标签页明确选用一份清单，用于独立打开的共享 SDK 文件或项目选择存在歧义时 |
| `<Space>uJ` | 切换“Filelist 直接文本匹配”，在 LazyVim `<Space>u` 菜单显示状态 |

直接文本匹配默认关闭。开启后，C/C++、Python 的 `gd/gr` 跳过 LSP 定义/引用请求，直接显示清单内文本
候选，不等待 2 秒超时。字面量 include 仍先按清单定位；无头文件候选或宏 include 转为光标下
完整词的清单文本匹配。清单缺失或为空时仅提示，不转回 LSP 或扩大搜索范围。
再次切换恢复 LSP 优先。切换时取消本模块所有待返回的语义请求，忽略旧响应；不停止 LSP
客户端，补全、诊断和其他语言导航保持原行为。

开关在当前 Neovim 会话全局生效，重启默认关闭；在 `lua/config/options.lua` 设置
`vim.g.filelist_text_only = true` 可默认开启。各标签页仍使用各自选定的清单。

`:FilelistUse` 的路径按原文输入：空格不加引号，`$`、`%` 等保持字面量，仅展开开头的 `~/`；不启用会自动展开参数的文件名补全。无参数执行该命令恢复自动选择。

开关关闭且没有清单时保持现有 `gd/gr` 行为。清单模式的映射在 C/C++、Python 缓冲区可用，即使 LSP 尚未附着；LSP 后续附着也不能把该行为覆盖掉。其他语言保持原导航。

### 头文件的选择

- 支持 `#include "dp.h"` 和 `#include <dir/dp.h>`。宏形式 `#include HEADER_NAME` 在默认模式下交给 LSP，不能把宏名当作文件名。
- 按完整路径分段匹配清单路径后缀；带目录的 include 不因未匹配而悄悄退化为任意同名 basename。引号 include 还可以考虑相对于当前文件的规范化路径，但目标必须在清单内。
- 候选去重后如果仍有多个，不根据扫描顺序猜测架构或 SDK。例如两个 SDK 都有 `dp.h` 时，让用户从完整路径中选择。
- 默认模式下清单无候选时可以尝试 LSP；LSP 成功的结果可能位于清单之外。清单不能推导真实的 `-I` 顺序或宏条件。

### 符号与引用的边界

- 清单搜索先用 rg 找完整标识符，再用包内 C/C++/Python Tree-sitter 对有匹配的文件做语法筛选；
  不请求 LSP、不读取编译数据库、不增加依赖。`.h` 按来源缓冲区的 C/C++ 模式解析。
  Python 来源遇到 `.h` 默认按 C 解析，其余文件按自身后缀选择解析器；未支持的后缀只保留文本匹配。
- `gd` 优先保留符号的定义位置：函数、带结构体体的结构体/联合体及其成员、数组、全局/局部变量、
  函数体的参数、宏名、`typedef`、枚举类型及枚举项；C++ 还支持类和 `using` 类型别名。
  有定义时不混入调用、函数原型、结构体前置声明、注释或字符串；无初始化的 `extern` 不当作定义。
  `int x;`、`int a[8];` 和函数指针变量是定义候选，不依赖是否带分号；初始化表达式中的同名引用不算定义。
  支持多行函数头、自定义/指针返回类型、参数含函数指针和同一行带分号的函数体；不以整行是否有分号判断。
- `gr` 只排除识别出的符号名定义位置，保留同一行的初始化引用、赋值、数组/成员访问、递归调用和宏使用；仍可能包含函数原型、
  注释、字符串和其他同名符号，不能宣称是准确调用图。`:FilelistGrep` 不做语法筛选。
- 未识别到符号定义时，`gd` 提示并回退全部文本。解析器不可用或
  文件读取失败会提示；未筛选文件的文本仍可通过 `gr` 或 `:FilelistGrep` 查看。宏展开、条件编译及符号
  归属仍需 LSP；Tree-sitter 的语法候选不等于语义定义。解析仅在本次搜索使用，不建立持久索引。
- LSP 保留现有 `compile_commands.json` 和交叉编译器配置，不从 filelist 猜测编译参数，不过滤 LSP 的返回文件。filelist 只限定文件定位与文本回退的范围。
- LSP 查询异步执行，首版等待上限建议为 2 秒；超时后取消该次请求并进入文本回退。请求发出后若用户切换来源缓冲区或移动到其他位置，不让过期响应自动跳转。
- 文本回退按完整标识符匹配。即使只有一个结果也显示“文本候选”供用户确认，不能把注释、调用或声明宣称为定义。
- `gr` 有语义结果时仅展示语义结果，不混入文本匹配；若用户仍想查看清单中的全部同名文本，使用 `:FilelistGrep`。语义结果数量依赖 LSP 索引覆盖和准备状态，不能由清单保证完整性。
- rg 只读取清单中明确列出的有效文件，按受控大小分批传递，避免大型 SDK 超出命令参数长度；不回退为扫描其父目录。结果通过 Snacks 展示，包含文件、行列与上下文，搜索异步并可取消。
- 文本回退读取磁盘内容，未保存修改可能尚未被反映；不为执行搜索而自动保存源码。LSP 对已打开缓冲区的处理保持原行为。

### Python 定义候选

使用 `nvim-filelist --root "$PWD" --ext py,pyi -- src tests` 可生成 Python 清单（普通终端需使用已安装工具的完整路径）。
支持 `def`、`async def`、装饰器包裹的函数/类、普通/默认/注解/可变参数、赋值与嵌套解包目标、属性赋值、
海象表达式、循环/推导式变量、`with/except ... as` 和显式导入别名。类属性和 `.pyi` 定义也纳入候选。

Python 没有统一的变量声明语法，普通赋值和属性赋值均视为绑定候选，不尝试判断是否为首次赋值。
`+=` 等更新、下标写入、类型注解中的类型名、默认值及右侧表达式中的读取保留为引用文本。
普通导入名保留为引用，以便 `gd` 优先定位清单中实际的函数/类定义；显式 `as alias` 视为本地绑定。
不展开模块路径、不追踪跨模块别名、不分析动态属性或执行 Python 代码；这些语义解析仍由 Pyright 完成。
Python 的 `#include ...` 注释不会触发 C/C++ 头文件定位。开关开启时完全跳过 Pyright 跳转请求；关闭后恢复 LSP 优先。

## 项目与共享 SDK

自动从当前文件的祖先目录寻找最近的 `tree_t.f`，其次考虑 Neovim 工作目录的祖先。主动切换清单使用 `:FilelistUse`，选择保留在当前标签页。

从项目跳到外部 SDK 时保留来源清单，使后续在 SDK 内的查找仍有范围。自动选择过的清单仅在当前文件属于其范围时复用；文件所属项目存在另一份更近清单时选择该项目。显式选用的清单优先，重新执行 `:FilelistUse` 可切换或恢复自动选择。

两个项目共享同一个 SDK 时，各标签页可使用不同清单。独立打开 SDK 且无法推断项目时，提示显式选择，不扫描磁盘猜项目。清单仅为文本输入，不执行其中的内容。

## 实施与验收范围

实现拆成个人配置中的导航模块、生成脚本，以及离线包安装和使用说明。真实项目中的扫描目录由用户运行命令时传入，不写入通用配置。生成脚本随包安装到 `tools/bin`，检查其依赖；普通终端和 Neovim 内均给出明确调用方式。

验收需覆盖：两个扫描目录及项目外 SDK、空格路径、重复与失效条目、显式目录链接与内部链接、重建去掉已删除文件、扫描失败保留旧清单、Git/worktree 本地排除；include 唯一与重名候选；无 LSP 的 `gd/gr` 回退、后续 LSP 附着、异步超时和过期响应；文本匹配标识及不越出清单；共享 SDK 导航范围和 `Ctrl-o` 返回。仅在这些检查通过后更新离线发布包。

仓库中的可重复检查：

```bash
nvim -u NONE -n --headless -l scripts/test-filelist.lua
XDG_CONFIG_HOME="$PWD/config" nvim --headless \
  '+lua dofile("scripts/test-filelist-integration.lua")'
```

第一项覆盖生成器与导航边界（真实 Git/rg、模拟 LSP）；第二项使用完整 LazyVim、真实选择器和
clangd/pyright/verible。`scripts/verify-release.sh` 还会对干净安装后的配置与工具执行这两项。
